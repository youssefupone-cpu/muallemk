# إصلاح: رسالة خطأ invoke غير واضحة (result:null, status:error)

- **التاريخ**: 2026-08-02
- **الحالة**: fixed
- **المنطقة**: `backend/app/plugins/router.py:119-126` — `POST /plugins/{name}/invoke`
- **الخطأ**: عند استدعاء إضافة بباراميتر خاطئ (مثلاً تمرير `{subject,grade}` بدلاً من `{grades:[...]}` لإضافة grades-tool)، كانت الاستجابة `{"result": null, "status": "error"}` بلا تفسير — المستخدم لا يرى السبب.
- **السبب الجذري**: الـ router لا يرفق `last_error` في الاستجابة عند الفشل (`Plugin._record_failure` يخزنه داخلياً لكنه لا يُسلَّم للمتصل).
- **الحل**: أضفت ربط `resp["error"] = p.info.last_error` عند `status == "error"|"disabled"` في `invoke_plugin` — انظر `backend/app/plugins/router.py:126-128`.
- **التحقق**: اختبار واحد معزول عن ترتيب التنفيذ `test_http_invoke_reports_error_then_success` في `backend/tests/test_plugins.py` — يمر معزولاً وفي المجموعة الكاملة بأي ترتيب (تحققت 3 مرات متتالية `pytest tests/test_plugins.py -q` → 10/10). المجموعة النهائية: **54/54 تم المرور** عبر `pytest tests/ -q` + `ruff check` نظيف + `tsc --noEmit` نظيف.
