# مشاكل-حلول/ — سجل المشاكل والأخطاء والحلول

هذا المجلد يسجّل كل المشاكل والأخطاء والإصلاحات والاقتراحات المكتشفة أثناء العمل.

## القاعدة الإلزامية
**عند اكتشاف أي مشكلة/خطأ/اقتراح أثناء العمل، سجّله في هذا المجلد.**

## الأقسام
| القسم | المجلد | متى تستخدم |
|-------|--------|------------|
| أخطاء برمجية | `bugs/` | خطأ/عطل في الكود |
| مشاكل عامة | `problems/` | مشكلة تصميم/معمارية/أداء |
| إصلاحات | `fixes/` | حل تم تطبيقه |
| اقتراحات | `اقتراحات/` | فكرة تحسين مستقبلية |

## بنية ملف المشكلة
```markdown
# <عنوان المشكلة>

- **التاريخ**: YYYY-MM-DD
- **النوع**: bug | problem | fix | suggestion
- **الوضعية**: plan | build | tester | matching | backend | reviewer | design
- **الحالة**: open | fixed | closed
- **الأولوية**: low | medium | high | critical

## الوصف
(وصف المشكلة/الخطأ بوضوح)

## الخطوات لإعادة الإنتاج (للأخطاء)
1. ...
2. ...

## السبب الجذري
(إن وُجد)

## الحل / الإصلاح
(سجّل الحل هنا عند تطبيقه — إلزامي مع تحديث الحالة من `open` إلى `fixed`)

## الملفات المتأثرة
- ...
```

## اصطلاح التسمية (إلزامي — اسم معبّر)
- **لا تستخدم أسماء عامة** (`issue1.md`, `problem.md`).
- الصيغة: `YYYY-MM-DD-وصف-مختصر-معبّر.md` يعبّر عن جوهر المشكلة.
- أمثلة:
  - `2026-08-02-فشل-اتصال-قاعدة-البيانات.md`
  - `2026-08-02-خطأ-تسجيل-الدخول-بعد-التحديث.md`
- الاسم العربي المقروء أفضل؛ وإن كان إنجليزياً فليكن وصفيّاً: `2026-08-02-db-connection-timeout.md`.

## إدارة الحالة
- **open**: تم اكتشافها.
- **fixed**: تم إصلاحها (الحل مسجّل في الملف).
- **closed**: تأكد الإصلاح وأُغلق.

## قاعدة الحل
- كل ملف مشكلة يجب أن يوثّق **السبب والحل** (إن وُجد) داخل نفس الملف.
- عند تطبيق الحل: حدّث الحالة إلى `fixed` وأضف سطراً في "سجل".
