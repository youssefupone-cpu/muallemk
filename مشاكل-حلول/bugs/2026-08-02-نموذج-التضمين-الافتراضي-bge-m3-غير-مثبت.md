# خطأ: نموذج التضمين الافتراضي bge-m3 غير مثبت → RAG يفشل 404

- **التاريخ**: 2026-08-02
- **الحالة**: fixed
- **المنطقة**: RAG — `app/rag/embeddings.py` / `app/core/config.py`
- **الأثر**: فهرسة أي مستند تفشل برسالة `Client error '404 Not Found'` من Ollama على `/api/embed`، وبالتالي **لا يمكن اختبار سؤال RAG الحقيقي** رغم أن Ollama يعمل والنموذج embed صحيح.
- **السبب**: `settings.rag_embed_model = "bge-m3"` افتراضياً، لكن bge-m3 غير مثبت في Ollama المحلي لهذا الجهاز. النماذج المثبتة المتوفرة (من `GET /api/tags`): `nomic-embed-text` (261MB)، `all-minilm:latest` (43MB). عندما يُطلب نموذج غير مثبت، يعيد Ollama `404 Not Found` — لا رسالة «model not found» (السلوك الافتراضي للإصدار الحالي).
- **الحل**:
  1. تغيير الافتراضي إلى `nomic-embed-text` في `app/core/config.py` (متوفر/شائع/خالٍ من الترخيص).
  2. السماح بالتجاوز عبر `.env` (`rag_embed_model=...`) — كان متاحاً أصلاً عبر pydantic-settings.
  3. إضافة تحقق سريع في `OllamaEmbedder.embed` يرهن النموذج بإنذار لو كان `404`، مع إسقاط اشتراط "bge-m3" المذكور في docstring.

## التحقق (آخر اختبار فعلي)
- قبل: `POST /rag/index/42` → `404 Client error '404 Not Found' ... /api/embed`
- بعد الإصلاح (مؤكد فعلياً في 2026-08-02): رفع `test_book.txt` (id=45) ثم `POST /rag/index/45` → `{"document_id":45,"indexed":1,"dim":768}` (20.4s)؛ ثم `POST /rag/query` يعيد chunk مع `score` والإجابة عبر SSE `POST /rag/ask` تبث `conversation` + `sources`. الإصلاح يعمل ويُختبر عبر TestClient وبشكل حي.
