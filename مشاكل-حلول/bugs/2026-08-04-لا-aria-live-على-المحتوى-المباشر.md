# مشكلة: لا aria-live على المحتوى اللي يُبثّ (Streaming Accessibility)

- **التاريخ**: 2026-08-04
- **النوع**: bug (accessibility / WCAG 2.2)
- **الوضعية**: matching
- **الحالة**: fixed
- **الأولوية**: medium
- **الملف المتأثر**: `frontend/src/components/chat/ChatMessage.tsx`

## الوصف

عند الـ streaming للـ LLM (SSE)، يتم إظهار النص تدريجياً كلما وصل chunk جديد. لكن المكونات لا تستخدم `aria-live` — مما يعني أن **مستخدمو قارئ الشاشة (screen readers) لن يسمعوا الرسائل الجديدة أبداً** حتى يقرأوا الصفحة يدوياً.

## الأدلة

```tsx
// frontend/src/components/chat/ChatMessage.tsx
export function ChatMessage({ message }: { message: Message }) {
  return (
    <div className="message-content">
      {message.content}   // ← محتوى يُبثّ تدريجياً — لا aria-live
    </div>
  );
}
```

## التأثير

- **WCAG 2.2 Level AA**: فشل في Success Criterion 4.1.3 (Status Messages).
- مستخدمو الـ screen reader لن يسمعوا الردود الجديدة — يعتقدون أن الـ LLM "توقّف".
- يُخفق التقييم الأمني للوصولية.

## الحل

```tsx
export function ChatMessage({ message }: { message: Message }) {
  const isStreaming = message.isStreaming;

  return (
    <div
      className="message-content"
      aria-live={isStreaming ? "polite" : undefined}
      aria-atomic={isStreaming ? "false" : undefined}
      aria-relevant="additions text"
    >
      {message.content}
    </div>
  );
}
```

### إضافة عالمية للـ ChatPage:

```tsx
// في ChatPage — أضف region للرسائل مع aria-live
<div
  ref={messagesEndRef}
  aria-live="polite"
  aria-reason="conversation"
  className="messages-container"
>
  {conversations.map(msg => <ChatMessage key={msg.id} message={msg} />)}

```
