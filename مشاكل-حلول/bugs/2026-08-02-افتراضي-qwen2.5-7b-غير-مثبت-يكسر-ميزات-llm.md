# خطأ: النموذج الافتراضي qwen2.5:7b غير مثبت → كل ميزات LLM تفشل 500 من الواجهة

- **التاريخ**: 2026-08-02
- **النوع**: bug
- **الوضعية**: tester
- **الحالة**: fixed
- **الأولوية**: critical

## الوصف
أي طلب LLM من الواجهة (توليد تقرير، محادثة، سؤال كتب) يفشل بـ `500 Internal Server Error` — لأن الافتراضي `qwen2.5:7b` غير مثبت في Ollama المحلي.

## الخطوات لإعادة الإنتاج
1. شغّل الواجهة + الباكند + Ollama المحلي.
2. افتح `/plugins` واملأ «موضوع التقرير» ثم اضغط «توليد تقرير».
3. لاحظ `500` في سجل uvicorn.

## السلوك الفعلي
```
POST /plugins/reports/report HTTP/1.1" 500 Internal Server Error
litellm.llms.ollama.common_utils.OllamaError: {"error":"model 'qwen2.5:7b' not found"}
```

## السلوك المتوقع
التقرير يُولَّد باستخدام نموذج مثبت محلياً.

## السبب الجذري
- `backend/app/core/config.py:21`: `default_model = "qwen2.5:7b"` — غير مثبت.
- `frontend/src/lib/settings.ts:29`: `model: 'qwen2.5:7b'` في DEFAULT_SETTINGS + hint في PROVIDERS.
- نماذج Ollama المتاحة فعلياً: `gemma3:1b-it-qat` (1.0GB — عربية سليمة، ~4.3 tok/s)، `qwen3.5:2b-q4_K_M`، `qwen2.5-coder:1.5b`، `starcoder2:3b-q4_K_M`، `all-minilm` (تضمين).

## الحل / الإصلاح
غيّر الافتراضي إلى النموذج المثبت المحلي الأنسب للعربية `gemma3:1b-it-qat` في موضعين:
1. `frontend/src/lib/settings.ts`: hint + `model: 'gemma3:1b-it-qat'`.
2. `backend/app/core/config.py`: `default_model = "gemma3:1b-it-qat"`.

**التحقق (فعلياً)**: بعد إعادة تشغيل الباكند، `POST /plugins/reports/report` من الواجهة (موضوع «المشتقة») → `200 OK` والتوليد يبدأ (بطيء بسبب غياب GPU — issue منفصل). إضافة إلى `68 passed` (pytest) و `tsc --noEmit` نظيف.
