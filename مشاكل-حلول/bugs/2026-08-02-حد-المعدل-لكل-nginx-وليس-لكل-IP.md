# حد المعدل لكل nginx وليس لكل IP خلف الوكيل

- **الحالة**: fixed (2026-08-02 — حلقة إصلاحات المراجعة، Development)

## الحل المنفذ
`_client_host(request)` تقرأ أول عنصر من `X-Forwarded-For` (يضبطه nginx من
`$remote_addr` الحقيقي في `frontend/nginx.conf:33`) وتعود إلى `client.host`
عند غيابه (وصول مباشر). الوكيل موثوق في بيئة docker-compose المعتمدة.
- **التصنيف**: Major (انحراف عن الوظيفة الموعودة في بيئة النشر المعتمدة)
- **الموقع**: `backend/app/core/rate_limit.py:22` + `docker-compose.yml` + `frontend/nginx.conf`

## المشكلة
`rate_limiter` يبني المفتاح من `request.client.host`:
```python
host = request.client.host if request.client else "unknown"
key = (request.url.path, host)
```
في نشر docker-compose المعتمد، جميع الطلبات تمر عبر nginx كوكيل عكسي إلى backend:8000،
فيكون `request.client.host` دائماً عنوان حاوية nginx → **حصة 60/دقيقة تصبح مشتركة لجميع
المستخدمين** بدلاً من "لكل IP" كما يعد docstring (`rate_limit.py:3-5`).

## السبب
`client.host` هو عنوان الـ TCP peer المباشر، وليس عنوان العميل الأصلي؛ لا يوجد قراءة
لاستعلام `X-Forwarded-For` مع ضبط `proxy_headers` في uvicorn.

## الحل المقترح
1. تشغيل uvicorn مع `--proxy-headers` + `--forwarded-allow-ips` محدود، أو
2. قراءة أول عنصر من `X-Forwarded-For` فقط (مع توثيق أن الوكيل موثوق في هذه البيئة)، أو
3. توثيق القيد صراحةً وقبول الدلالة المشتركة إن كانت كافية للحماية من الدورات العشوائية.

## الأثر
حاجز ضد الدورات العشوائية يبقى فعّالاً إجمالياً؛ الضعف في التمايز بين المستخدمين فقط.
