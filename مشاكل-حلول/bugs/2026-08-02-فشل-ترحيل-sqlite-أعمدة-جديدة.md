# فشل ترحيل SQLite عند إضافة أعمدة NOT NULL لقاعدة قديمة

- **التاريخ**: 2026-08-02
- **النوع**: bug
- **الوضعية**: tester
- **الحالة**: fixed
- **الأولوية**: high

## الوصف
عند تشغيل التطبيق على قاعدة قديمة (بدون عمودي `updated_at` في conversations و `metadata` في messages) يفشل الإقلاع — الخادم لا يبدأ إطلاقاً.

## الخطوات لإعادة الإنتاج
1. أنشئ قاعدة بجداول `conversations`/`messages` بالبنية القديمة (بدون الأعمدة الجديدة) مع صف قديم.
2. شغّل `init_db()` (يُستدعى من `lifespan` في `main.py:28`).
3. لاحظ فشل الترحيل.

## السلوك الفعلي
خطأان متتاليان أثناء `init_db`:
1. `sqlite3.OperationalError: Cannot add a column with non-constant default` — عند `ALTER TABLE ADD COLUMN updated_at TEXT NOT NULL DEFAULT (datetime('now'))` (SQLite يرفض الـ default غير الثابت في ALTER).
2. بعد تغيير الـ default إلى `''`: `sqlite3.IntegrityError: NOT NULL constraint failed: conversations.updated_at` — عند `UPDATE ... SET updated_at = created_at` لأن `created_at` في الصفوف القديمة `NULL` (أُدخلت بلا قيمة) والنسخ إلى عمود NOT NULL يفشل.

## السلوك المتوقع
ترقية سلسة: إضافة الأعمدة دون هدم البيانات، وتهيئة القيم من الحقول الموجودة.

## السبب الجذري
- SQLite يسمح فقط بـ constant default في `ALTER TABLE ADD COLUMN` (لا `datetime('now')`).
- صفوف قديمة تحمل `created_at = NULL` (العمود الأصلي بلا `DEFAULT`).

## الحل / الإصلاح
في `backend/app/core/db.py` `init_db`:
- إضافة العمود عبر المُساعد `_add_column` بصيغة `TEXT NOT NULL DEFAULT ''` (ثابت).
- تهيئة القيم بـ COALESCE لتحمّل NULL:
  `UPDATE conversations SET updated_at = COALESCE(created_at, '') WHERE updated_at = ''`
- التأكد من أن `_add_column` يتحقق بـ `PRAGMA table_info` قبل ALTER (لا يلمس الجداول المحدّثة بالفعل).

## الملفات المتأثرة
