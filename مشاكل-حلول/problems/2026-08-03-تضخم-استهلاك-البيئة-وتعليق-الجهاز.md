# تضخم استهلاك البيئة وتعليق الجهاز

## الأعراض
- الجهاز (RAM 7.5GB، 4 أنوية) يتجمد أثناء جلسات opencode.
- عملية opencode وحدها: **99.5% CPU و1.27GB RAM (16.1% من الذاكرة)**.
- بطء شديد في كل استجابة وفحص ملفات.

## الأسباب الجذرية (بالأدلة من الفحص الفعلي)

### 1. 🔴 قائمة المهارات الضخمة محقونة في كل طلب — السبب الرئيسي
- عدد المهارات المكتشفة: **~1361** = 543 (`~/.opencode/skills`) + 719 (`node_modules/ecc-universal`) + 99 (`~/.agents/skills`) + 98 (`~/.claude/skills`).
- opencode يحقن أسماء+أوصاف كل المهارات في system prompt في **كل** طلب (Issue #20647: 1500 مهارة = ~147K رمز = 56% من نافذة سياق 262K قبل أي محادثة!).
- عملياً: كل طلب كان يحمل ~100–150K رمز من قائمة المهارات وحدها → استهلاك هائل + حشو السياق.

### 2. 🟠 قاعدة بيانات 2.4GB
- `~/.local/share/opencode/opencode.db` = **2.4GB** (كل مخرجات التفكير ونتائج الأدوات لكل جلسة).
- Bun يعيّن (mmap) القاعدة كاملة في ذاكرة العملية → ضغط ذاكرة حقيقي حتى أثناء الخمول (Issue #22429).
- لا يوجد إعداد retention رسمي — التنظيف يدوي.

### 3. 🟠 plugin يشتغل على كل تعديل ملف
- `plugins/crg-plugin.ts`: على **كل** `file.edited` ينفّذ `code-review-graph update` (أمر CLI كامل بتحليل رسوم بيانية) + قبل كل `git commit` ينفذ `detect-changes` → على جهاز 4 أنوية = تعليق متكرر أثناء أي تعديل.

### 4. 🟡 node_modules 106MB داخل دليل الإعداد
- `ecc-universal` (22MB — 719 مهارة) + `effect` (47MB) + `sql.js` (19MB) — ثقل فحص/مراقبة.

### 5. 🟡 kimi-k2.5:cloud غير موجود محلياً
- غير مدرج في `ollama list` — إما عبر Ollama Cloud (يتطلب حساباً/اتصالاً) أو محاولة سحب عند كل إطلاق.

## الحل المطبق (2026-08-03)

| الإجراء | النتيجة |
|---|---|
| أرشفة `~/.opencode/skills` (543) إلى `skills-archive/` والاحتفاظ بـ **35** أساسية (روابط) | 543 → 35 |
| أرشفة `~/.agents/skills` (99) إلى `skills-archive/` والاحتفاظ بـ **14** | 99 → 14 |
| إزالة `node_modules/ecc-universal` + من `package.json` + من `plugin` في opencode.json | 719 → 0 |
| `export OPENCODE_DISABLE_CLAUDE_CODE_SKILLS=1` في `~/.bashrc` (منع اكتشاف `~/.claude/skills`) | 98 → 0 |
| نقل `crg-plugin.ts` إلى `plugins-disabled/` (إيقاف التنفيذ على كل تعديل) | توقف أوامر خلفية |
| `"snapshot": false` في opencode.json | إيقاف تتبع ملفات التراجع (كان يستهلك) |
| إنشاء `~/.config/opencode/cleanup-opencode.sh` | تنظيف قاعدة 2.4GB + الكاش (تشغيل يدوي) |
| إنشاء `~/.config/opencode/ollama-override.conf` (MAX_LOADED_MODELS=1, KEEP_ALIVE=10m, PARALLEL=1) | يقلل ذاكرة ollama (يتطلب جذراً) |

**الناتج**: ~1361 مهارة محقونة → **49** مهارة فقط = قائمة صغيرة (~4–6K رمز بدل ~150K) + لا أوامر خلفية ثقيلة + لا تتبع ملفات.

## متبقٍ على المستخدم (أمران)
1. بعد إغلاق كل جلسات opencode:
   ```bash
   ~/.config/opencode/cleanup-opencode.sh
   ```
   (ينسخ احتياطياً ثم يحذف opencode.db 2.4GB — تُعاد القاعدة نظيفة تلقائياً. **سيفقد سجل الجلسات التاريخي فقط**؛ لا مفاتيح API ولا إعدادات ولا مشاريع.)
2. مرة واحدة بصلاحيات الجذر (لتقليل ذاكرة ollama):
   ```bash
   sudo cp ~/.config/opencode/ollama-override.conf /etc/systemd/system/ollama.service.d/override.conf
   sudo systemctl daemon-reload && sudo systemctl restart ollama
   ```
3. أعد فتح المحطة (تحميل المتغير الجديد) وشغّل جلسة opencode جديدة.

## الاسترجاع (إن أردت المهارات المؤرشفة)
- أي مهارة من `~/.opencode/skills-archive/` أو `~/.agents/skills-archive/`: انسخها/اربطها إلى المجلد النشط المقابل ثم أعد التشغيل.
- إعادة تفعيل ecc-universal: أعد `"ecc-universal"` إلى `plugin` في opencode.json + `npm i` في `~/.config/opencode/`.
