## 1. الأمان — العيوب الحرجة الجديدة (5 — لم تكن موجودة من قبل)

### 1.1 🔴 API Keys تُرسل من المتصفح إلى الخلفية في الـ POST body
- **المستوى**: Critical
- **الملف**: `frontend/src/lib/api.ts:42,162,268,309,509,637`
- **المشكلة**: `api_key` يُرسل في `JSON body` — مرئي بالكامل في Network Tab، وبصيغة واضحة في proxy logs وserver logs.
- **الوضع السابق**: مذكور كـ "ملاحظة" في التقرير السابق (§2.1) لكن دون توثيق كـ bug. الآن موثّق كـ bug منفصل.
- **الحل**: [Transfer api_key إلى Header](fixes/2026-08-04-نقل-api-key-من-body-إلى-header.md) كخطوة مؤقتة؛ [Backend-as-Proxy للمفاتيح](bugs/2026-08-04-api-keys-من-الواجهة-الأمامية-للكخادم.md) كحل نهائي.
- **الملف المنشأ**: `مشاكل-حلول/bugs/2026-08-04-api-keys-من-الواجهة-الأمامية-للكخادم.md`

### 1.2 🔴 `|| true` في CI يلغي فحص `npm audit`
- **المستوى**: Critical
- **الملف**: `.github/workflows/ci.yml:71`
- **المشكلة**: `npm audit --audit-level moderate || true` — يجعل الخطوة تنجح دائماً حتى مع ثغرات حرجة.
- **الحل**: إزالة `|| true`، رفع المستوى إلى `high`.
- **الملف المنشأ**: `مشاكل-حلول/bugs/2026-08-04-ci-npm-audit-مع-ture-يُلغي-فحص-الأمان.md`

### 1.3 🔴 جميع الخدمات Docker تعمل كـ root
- **المستوى**: High
- **الملفات**: `backend/Dockerfile`, `frontend/Dockerfile`, `docker-compose.yml`
- **المشكلة**: لا `USER` statement في أي Dockerfile؛ جميع الخدمات تعمل بامتيازات root.
- **الحل**: إضافة `USER 1000` في كلا Dockerfile، و `user: "1000:1000"` في compose.
- **الملف المنشأ**: `مشاكل-حلول/bugs/2026-08-04-الخدمات-تعمل-كـ-root-في-الـ-Docker.md`

### 1.4 🟠 لا حدود موارد (mem/cpu) في Docker Compose
- **المستوى**: High
- **الملف**: `docker-compose.yml`
- **المشكلة**: لا `mem_limit` ولا `cpus` على أي خدمة → Ollama/Backend يمكنها استهلاك كل الذاكرة RAM.
- **الملف المنشأ**: `مشاكل-حلول/bugs/2026-08-04-لا-حدود-موارد-في-الـ-Docker-Compose.md`

### 1.5 🟠 `.env` يُحمّل API Keys داخل الحاوية
- **المستوى**: High
- **الملف**: `docker-compose.yml:5-6`
- **المشكلة**: `env_file: .env` يحمل كل المتغيّرات (بما فيها secrets) داخل الحاوية.
- **الحل**: استخدام Docker secrets أو env vars من CI فقط.
- **الملف المنشأ**: `مشاكل-حلول/bugs/2026-08-04-env-يحمل-مفاتيح-API-داخل-الحاوية.md`

### 1.6 🟡 Zip Slip في `restore_backup`
- **المستوى**: Medium
- **الملف**: `scripts/backup.py:76-97`
- **المشكلة**: `zf.extractall()` دون فحص مسارات الملفات → path traversal.
- **الحل**: [إصلاح Zip Slip](fixes/2026-08-04-إصلاح-Zip-Slip-في-restore-backup.md)
- **الملفات المنشأة**: `مشاكل-حلول/fixes/2026-08-04-إصلاح-Zip-Slip-في-restore-backup.md`

### 1.7 🟡 تسريب تفاصيل الأخطاء في HTTP responses (3 مواقع)

- **الملفات**: `backend/app/books/router.py:231`, `backend/app/websearch/router.py:32`, `backend/app/main.py:175`
- **المشكلة**: `str(e)` و `str(e)[:300]` تُرجع في `detail` — تسرب أسماء نماذج LLM، مسارات ملفات، stack traces.

## 2. Docker / CI — العيوب الجديدة (5)

### 2.1 🟠 لا Docker build في خطوة CI
- **المستوى**: Medium
- **الملف**: `.github/workflows/ci.yml`
- **المشكلة**: الـ CI يختبر فقط (lint + test) لكنه لا يبني صورة Docker. `lancedb==0.36.0` (غير موجود) لن يُكتشف.
- **الملف المنشأ**: `مشاكل-حلول/problems/2026-08-04-لا-Docker-build-في-خطوة-CI.md`

### 2.2 🟠 استخدام صور `:latest` غير المُثبّتة
- **المستوى**: Medium
- **الملف**: `docker-compose.yml:31,42`
- **المشكلة**: `ollama/ollama:latest` و `searxng/searxng:latest` — non-reproducible.
- **الحل**: Pin إلى إصدارات محددة.

### 2.3 🟡 لا `HEALTHCHECK` في backend Dockerfile
- **المستوى**: Low
- **الحل**: إضافة `HEALTHCHECK CMD curl -sf http://localhost:8000/api/health || exit 1`.

### 2.4 🟡 لا log rotation في Docker
- **المستوى**: Low
- **الحل**: `log_driver: json-file` + `max-size: 10m` + `max-file: 3`.

### 2.5 🟡 Ollama/SearXNG مُعرّضين على المنافذ في الـ dev
- **المستوى**: Low
- **الحل**: استخدام `expose` بدلاً من `ports` للخدمات الداخلية.
